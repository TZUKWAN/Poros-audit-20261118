# 场景智能体重构目标与验收

目标：一句需求构建真实可复用场景，工作模式能加载并执行；首页只有需求输入、模式和结果；历史/设置/场景管理可访问且无横向溢出。用户要求的 100% 成功落实为已定义的可控验收用例 100% 通过，不以模拟响应、跳过执行或将未验证检查标为通过达成。

## 必须纠正的事实

现有界面可加载不代表场景可用。当前生产启动器把技能说明当执行器、用能力名称猜 tools/call 名称、缺少上下游数据传递、用泛化跳过伪装为 passed，且默认模型端口 8317 未在线。上一轮改动中 `construction-validation` + skipped trace + passed task/generalization 不能作为真实成功证据，必须移除。新方案明确区分定义构建成功和实际运行验证。

## 技术路线与边界

保留已有存储、项目、历史、Memory、Provider、场景生命周期仓库和可用管理能力；替换生产启动器中的示范编排路径。Web 主流程使用独立的定义构建与真实执行服务，旧五闸门内核保留兼容并审计。模型不可用时保存的基础定义标记为离线生成、运行未验证，不冒充模型规划或任务完成。配置/真实密钥不进入日志、对话、Memory 或源码。ARES/METIS 不在本轮修改范围。

风险：外部模型/工具离线、未授权文件和外部发送无法保证成功；这些应产生准确状态与可操作恢复入口。绝不能为了“100%”绕过验收。

交付：可用本地服务和侧边浏览器、修复源码、针对性测试、审计报告和恢复状态。
