## 1. 定位与核心命题

SceneFlow 是"一句话构建、处处复用"的场景工作台。v1.0 之前它与 n8n/Dify 同构——资产押在**冻结计划**上，第 N 次运行不会比第 1 次更好。分寸账本改造把资产位换掉：

> **计划降级为缓存，账本（约束/先例/统计）成为唯一复利资产。**
> 北极星指标 = 第 N 次人工介入次数曲线（单调下降 = 越用越牛逼的数学形式）。

技术上的本质变化：系统从"流程执行器"变成"**带验证闭环的自治执行体**"——人的每个信号被结晶为可执行判据，下次运行自动注入、自动检查、自动降档。

## 3. 分寸账本核心原理

### 3.1 四条铁律（防做歪的设计约束）

1. **只结晶，不发明**——每条约束必须带人的信号出处（`ConstraintOrigin`：原话/diff 摘要/at/runId），agent 永不自动生成约束。
2. **计划是缓存**——重规划随时整个换掉计划，账本一字不动。
3. **置信度外生于账本**——只用统计（连续无干预通过、打回衰减），禁用模型自评。
4. **北极星 = 介入次数曲线**——所有功能服务于这条单调下降曲线。

### 3.2 数据模型（ledger.ts）

账本随场景记录持久化（`ScenarioRecord.ledger`，可选字段保证老记录兼容）：

```
ScenarioLedger
├── constraints: Constraint[≤200]        分寸条款
│     { id:"c-xxxx", clause 人可读条款, scope: goal|step|capability|acceptance|output,
│       kind: advisory|must_contain|must_not_contain, pattern 可执行判据,
│       origin:{type: reject|gate-edit|feedback|guide|artifact-edit, text 原话, at, runId},
│       confirmedAt(null=pendingConfirm), hits 自检拦下次数, active, supersededBy }
├── runStats { runs, accepted, rejected, corrected, consecutiveClean }
├── gateStats   "1".."5" → { passes, rejects, edits, lastEventAt }
├── inputPatterns[≤50]  { digest, at, outcome }   事件源：digest 命中 + 衰减计数
└── interventions[≤200] { runId, at, gatesAnswered, questionsAnswered, correctionsGiven, total }
                            ↑ 北极星曲线数据源
```

### 3.3 教学 ≠ 分寸（gate-classify.ts，纯函数）

**判定标准：下次重规划，模型自己能不能想对？**

| 信号 | 分类 | 归宿 |
|---|---|---|
| 闸1 改 goal 措辞 / 闸2 改步骤标题顺序 | 教学 | 只更新计划缓存，不入账本 |
| 闸3 换能力（偏好） | 分寸 | `步骤「{node}」使用「{cap}」` → pendingConfirm |
| 闸4 新勾验收项（标准） | 分寸 | `验收必须包含：{人话}` → must_contain, pattern=null 走 judge |
| reject + 原话 | 分寸 | 去否定前缀，**原话即条款**（scope 按闸门 1→goal/2→step/3→capability/4→acceptance/5→output） |
| 👎 + 原因 / guide-run / 产出编辑 | 分寸 | output scope，pendingConfirm |

**质量门槛**：去标点后 <4 字或全是否定/语气词（"不对""重做"…）→ 只记事件，不生成提案。
**冲突粗检**：条款字符 bigram Jaccard ≥0.6 → `conflictWith` 标记，签约面并排提示。

## 4. 置信度引擎与路由（confidence.ts / route.ts）

### 4.1 置信度公式（外生统计，禁模型自评）

```
confidence = 1.0 × consecutiveClean − 0.8 × Σdecay(rejected) − 0.5 × Σdecay(corrected)

decay(at) = exp(−daysSince(at) / 14)     事件半衰期 14 天
窗口 30 天外的过期事件不计
```

- 事件源 = `ledger.inputPatterns`（每 run 收尾一条 {digest, at, outcome}）
- `consecutiveClean` 只由**有人值守**的 accepted 推进（§5 无人值守规则）

### 4.2 tier 分档与双路路由（match 命中后、执行前）

```
tier = confidence ≥3 → replay（重放）｜ ≥1 → spot（抽查）｜ else → full（全开）

route = resolveRoute(ledger, { degraded, digest }):
  degraded                  → 强制重规划（禁重放，防降级死锁——自动化路径另行拦截）
  digest命中 % 10 === 0     → 强制体检重规划（防静默漂移的复利防僵化机制）
  tier=replay 且 digest命中 → 重放 definition（豁免规划，不豁免自检）
  否则                      → 重规划（模板A约束+模板B先例注入 planner 上下文）
```

**重规划落点**：更新既有场景（`pinnedVersion+1`、账本一字不动、`sourceSignature` 保留）而非新建副本——"计划是缓存"的代码体现。重规划未固化（discard/规划器异常）→ **旧计划兜底**：回退执行缓存 definition + 交付卡标注。

### 4.3 digest 设计演进（本轮最重要的实机教训）

digest 是"同参数"的指纹，决定重放命中与体检触发。经历两次实机打脸：

| 版本 | 设计 | 实机结果 |
|---|---|---|
| v1（按规格） | sha1(排序槽位 k:v) | 永不命中——LLM 逐次解析槽位漂移 |
| v2 | 原文 + 槽位名:值 | 仍不命中——调试日志实锤**槽位名/数量/值摘要全漂移**（同一需求三次解析：`feedback_content+report_type` / `feedback+content_type+required_elements` / `feedback+output_format`） |
| v3（最终） | **sha1(归一化原文)**，槽位彻底不参与 | 强制体检 %10 路径实机触发 ✓ |

`normalizeRequirementText`：全角→半角、空白折叠、小写、去标点符号。参数区分语义由原文措辞承担——同场景不同参数必然体现在原文，措辞不同 → 保守重规划（安全侧默认）。

**方法论沉淀：实机排障别猜输入——加一行日志抓真实运行时值。**（这轮猜了 8 种槽位组合全错，日志一上立刻实锤。）

## 5. 运行时行为闭环

### 5.1 端到端时序（一次有人值守运行）

```
00 需求 → digest 计算
01 match() 命中场景 s → 读账本（ensureLedger 折算）
02 路由判定（full 档）→ 重放 / 重规划 / 强制体检
03 执行中 guide-run → corrected + 提案素材
04 产出落地 → 自检链（§5.3）
05 终态卡渲染（黄标/反馈行/修改产出）
06 反应窗 10min（先到先得）：👍/👎+原因/编辑/沉默
07 recordRunOutcome 事务 → runStats/gateStats/inputPatterns/interventions
08 快照广播 → sparkline/曲线刷新
```

### 5.2 反应窗与先到先得（server.ts）

有人值守成功 → `pendingFeedback` Map 挂 10min timer（`feedbackWindowMs` 可注入测试）：

- 👍 → accepted（显式）｜ 👎 → 原因必填（缺 → "400:"，不关窗），重复 runId → "409:" 幂等
- 👎/guide 原话 → `proposeConstraint` pendingConfirm 提案
- **修订产出（revise-output）**：`cancelFeedbackWindow` 先到先得撤销沉默，改记 corrected
- 沉默超时 → 弱 accepted（silent-accepted）

**无人值守规则（§9，一句话防夜跑放大错误）**：
`consecutiveClean 只由有人值守的运行推进`。定时/长程运行 `runs++`、失败可记 rejected（失败自证）、沉默**绝不记 accepted**——没人看过的成功不构成验证。实现：`attended` 按触发源打标（user=值守 / task、long-run=无人值守），`recordRunOutcome` 内分支。

**状态清理**：`suspected`（自检仍违规）断连胜但三个计数都不动——失败自证与好产出都不可信，不毒化统计。

### 5.3 产出自检修复链（selfcheck.ts，成本上限 2 次模型调用）

```
collect active constraints (confirmedAt≠null ∧ active ∧ ¬superseded)
 ├─ 空 → 直接交付
 ├─ 机械项 must_contain（pattern 子串/正则）/ must_not_contain → 规则判
 └─ advisory → judge（模板C，便宜模型一次调用，JSON 逐条 pass/fail，从严）
违规 → repairPrompt（违规条款+原产出）→ 执行模型重产出 ≤1 次
     → 复检只检违规项
仍违规 → 黄标交付（"未满足：{clause}"）+ run 标 suspected + hits++
```

从不阻断交付——judge 误判的代价是黄标+一轮修复，不是丢产出。

### 5.4 Edit-to-Accept（outputdiff.ts，最强信号）

用户改产出 = 最强分寸（付出了打字成本）。行级 LCS → eq/del/ins 算子序列 → 连续非 eq 游程归并为改动块：

| kind | 条款候选 |
|---|---|
| removed | `不要 {锚} 部分`（must_not_contain） |
| reworded | `{锚} 的表述应为「{after摘要}」`（advisory） |
| added | `{锚} 之后应包含「…」`（must_contain，**同类两次命中 → 机械升级**） |
| format | 不结晶（与内容条款隔离） |

尺寸控制：锚≤40 字（跳过 GOAL_MET 等执行器标记行）、片段≤200 字、每 run ≤5 块、原文不落账本只落锚+块。
修正事务 `applyOutputCorrection`：窗内=完整 corrected 事务；沉默已入账=撤销 accepted 改记 corrected；同 runId 多次编辑只计 1 次（interventions.correctionsGiven 判据）。

### 5.5 抽查态闸门自动通过（spot/full 档）

`gateStats[gate].passes ≥3 且 rejects==0 且 edits==0` → `handleGatePending` 自动 `orch.decide(approve)`，卡片不推，chat 通知"已按账本自动通过"。`autoPassedGates` Set 一次性防循环。legacy 档不生效。

**实机踩坑**：attachOrchestrator 会 reset `buildLedgerScenarioId`，而 launcher 顺序是 match（设值）→ attach（重置）→ 闸门——需在 `orch.start` 前按 `binding.replanScenarioId` 补绑。

### 5.6 并发竞态治理

- **账本写入**：所有变更走 `library.updateLedger(id, fn)`——store 串行化之上再按 id 排队（与 save 共队列），20 并发无丢更新（单测覆盖）。禁止任何调用方直接改 `record.ledger`。
- **重规划目标**：`RunBinding.replanScenarioId/replanConstraintText` 挂每运行 binding，不用共享闭包变量——实机撞上"用户运行 + 定时任务同时 full 档重规划"互相覆盖 → 重复场景，修复后各运行更新各自的定义版本。
- **双完成路径统一**：replan 更新分支曾只存在于 `finishBuild` 函数（restart-recovery 用），实机构建走的内联 `.then` 路径仍新建副本——两处必须同步修改（本轮教训：改共享逻辑先 grep 所有完成路径）。

## 6. Memory 边界（§13）

| | Memory | Ledger |
|---|---|---|
| 存什么 | 发生了什么（叙事） | 什么被验证过（结构） |
| 给谁用 | LLM 上下文垫料 | 行为门控（路由/闸门/自检） |
| 形态 | markdown 叙事 | 结构化条款+统计 |

唯一交点：条款签约时同步写一行 memory（`[ledger] 新增约束 c-x1: …`）。反向禁止：memory 内容永不自动变条款。（实机涌现：模型经 memory 看到约束 id 后在产出里诚实标注"源文本不含截止日，不做虚构推断"——模板A 精神的自发体现。）

## 7. 灰度与回滚（§16）

`settings.routingMode` 三档，场景详情面板可切换：

- **legacy**（默认上线档）：采集/签约面全开，路由/闸门动态化/自检不生效——零行为变化，纯攒数据
- **spot**：闸门动态化 + 自检启用，路由仍走旧路
- **full**：双路路由 + 强制体检 + 统一降级

每档改回即回滚，账本数据无损。统一降级（P7）：旧成功率规则（<50% ≥2次）保留为底线 + 账本置信度<0 触发。

## 9. 验证体系

**测试矩阵**（docs/分寸账本改造方案.md §18 全覆盖）：迁移幂等×3 / 并发 20 无丢更新 / consecutiveClean 折算=min(success,1) / 分类器四行 / 置信度衰减 / digest 归一 / 路由四行 / 自检四行 / feedback 400/409 / attended / 无人值守。

**实机验证**（WS 协议直驱，比 DOM 点击稳健）：验收剧本六步全通——打回→签约→👎→修订→零干预→黄标；长程运行 §9 四断言；full 档 Round A/B；五闸零干预自动通过；强制体检 %10 触发；双主题 + 375/720 实窗。

**过程抓出 5 个只有真实运行才暴露的 bug**：闭包并发竞态、双完成路径缺口、attach 时序重置、digest 双重漂移（槽位名 → 名+值全漂）、GOAL_MET 锚点污染。

## 10. 已知边界与演进方向

- replay 重放分支代码就位且单测覆盖，实机未自然走到（需 tier=replay + digest 命中双条件真实累积）
- 模板B 先例以元数据形态呈现（schema 不落产出原文，隐私边界）；format 块不结晶（独立 scope 需 schema 演进）；copied 事件无 schema 槽位
- 反应窗 timer 内存态（面板重启丢未决窗口）
- 跨场景偏好层不做（scope 字段留迁移钩子）
