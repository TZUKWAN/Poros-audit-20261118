# SceneFlow Dogfood 协议（两角色模型 §7）

> 目的：拿到第一个**带真实介入曲线的案例故事**——「介入曲线第二周低于第一周」。
> 选定垂类：**ares 竞赛备赛链**（领域库 132 赛事已就绪，场景颗粒度清晰，单人可执行）。
> 备选：metis 研究流水线（七阶段脊柱，信号更杂，适合二期）。

---

## 参与者

| 角色 | 谁 | 职责 |
|---|---|---|
| Builder | 你（或一名开发者） | 构建场景、签条款、维护账本面板 |
| Seller | 同一人或一名真实用户 | 跑 work、看结果、👍/👎/改产出 |
| 系统 | SceneFlow full 档 | 路由 + 自检 + 账本自动生命周期 |

> 两角色模型预言 seller-builder 杂交体（FDE 型）是第一楔子人群——dogfood 期间一人分饰两角即可。

## 协议（14 天）

| 阶段 | 天数 | 动作 |
|---|---|---|
| W1 基线 | D1-2 | 构建备赛场景（闸3 打回一次带原因 → 闸5 签约）；跑 3 次 work 记录介入数 |
| W1 结晶 | D3-7 | 每天跑 work；每次打回/修订都自然落账；每周五看介入曲线 |
| W2 复利 | D8-14 | 继续跑；观察条款 helped/hurt 累积、自动转正/退役是否触发；每周五对比介入数 |
| 验收 | D14 | 生成信任报告 → 检查介入曲线是否下降 |

## 验收问题（只有一个）

**介入曲线第二周是否低于第一周？**

- 是 → 拿到第一个「越用越牛逼」的真实案例故事
- 否 → 排查：条款是否太少（<2 条生效）？信号是否太弱（没有打回/修订）？灰度档位是否在 full？

## 数据埋点核查清单（W1 D1 检查一次）

- [ ] settings.routingMode = full
- [ ] 8375/ares 场景 ledger.attribution 存在（627+ 版本起自动带）
- [ ] gateStats 有值（founding build 的 approvals 已写入）
- [ ] 介入曲线 sparkline 在账本面板可见
- [ ] 经营头条在空态上方可见
